# Job과 CronJob

> Kubernetes의 Job은 특정 작업을 완료(complete)될 때까지 실행하기 위한 리소스이다.
> 웹 서버처럼 계속 돌아가는 워크로드와 달리, 연산, 이미지 처리, 데이터 분석, 리포트 생성같은 배치(batch)작업에 적합하다.
> CronJob은 이런 Job을 주기적으로 스케줄링해 실행한다.

---

## 1. 컨테이너 워크로드의 두 종류
- 장기 실행(Long-running) 워크로드: 웹 서버, 데이터베이스처럼 수동으로 중지할 때까지 계속 실행
- 배치(batch)작업: 연산, 이미지 처리, 데이터 분석, 리포트 생성 등 특정 작업을 수행한 뒤 종료

---

## 2. Docker에서의 배치 작업
두 숫자를 더하는 간단한 작업을 Docker로 실행하면, 컨테이너가 뜨고 -> 계산하고 -> 결과 출력 후 -> 종료된다.

```bash
docker run ubuntu expr 3 + 2
5

docker ps -a
CONTAINER ID   IMAGE     CREATED          STATUS                     PORTS
45aacca36850   ubuntu    43 seconds ago   Exited (0) 41 seconds ago
```

`STATUS`의 `Exited (0)` 에서 괄호 안 반환 코드 0은 작업이 성공적으로 완료됐다는 의미이다.

---

## 3. Kubernetes Pod로 옮기면 발생하는 문제
같은 작업을 Pod로 만들어 본다면

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: math-pod
spec:
  containers:
    - name: math-add
      image: ubuntu
      command: ['expr', '3', '+', '2']
```

```bash
kubectl create -f pod-definition.yml
kubectl get pods
# NAME      READY   STATUS    RESTARTS   AGE
# math-pod  0/1     Running   0          1d
```

그런데 컨테이너가 작업을 끝냈음에도, 잠시 후 보면 재시작(RESTARTS)횟수가 계속 늘어난다.
```bash
kubectl get pods
# NAME      READY   STATUS    RESTARTS   AGE
# math-pod  0/1     Running   3          1d
```

**왜 그럴까?**
Pod의 기본 재시작 정책(restartPolicy)은 `Always`이다.
즉 컨테이너가 종료되면 계속 재시작을 한다. 
일회성 작업에는 맞지 않으므로, 정책을 `Never` 또는 `OnFailure`로 재정의한다.

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: math-pod
spec:
  containers:
    - name: math-add
      image: ubuntu
      command: ['expr', '3', '+', '2']
  restartPolicy: Never
```
> `restartPolicy: Never`로 설정하면 명령 완료 후 Pod를 자동 재시작하지 않는다. 일회성 작업에 이상적이다.

---
## 4. Job 만들기
Pod 하나로는 **여러 개를 만들고 성공적으로 끝나도록 보장**할 수 없다. ReplicaSet은 항상 N개가 실행 중이도록 유지하는 반면,
Job은 지정한 작업이 성공적으로 완료될 때까지 Pod를 실행한다.
- ApiVersion: `batch/v1`
- kind: `Job`
- spec.tempate 아래에 기존 Pod 정의의 spec 내용을 그대로 옮겨 넣음.(ReplicaSet, Deployment와 동일한 템플릿 구조)

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: math-add-job
spec:
  template:
    spec:
      containers:
        - name: math-add
          image: ubuntu
          command: ['expr', '3', '+', '2']
      restartPolicy: Never
```

```bash
kubectl create -f job-definition.yml

kubectl get jobs
# NAME          DESIRED   SUCCESSFUL   AGE
# math-add-job  1         1            38s

kubectl get pods
# NAME                    READY   STATUS      RESTARTS   AGE
# math-add-job-<suffix>   0/1     Completed   0          38s
```

`RESTART 0` + `Completed` -> 성공 후 재시작을 시도하지 않았음을 의미한다.
작업 출력 확인은
```bash
kubectl logs math-add-job-<suffix>
```

**Job 삭제**
```bash
kubectl delete job math-add-job
```
>실무에서는 처리 결과를 영구 볼륨에 저장하거나, 리포트를 생성해 이메일을 보내는 식으로 Job의 산출물을 남긴다.

---
## 5. 여러 Pod 실행 - completions
`completeions`필드로 성공해야 하는 Pod 수를 지정한다. ex 3개

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: math-add-job
spec:
  completions: 3
  template:
    spec:
      containers:
        - name: math-add
          image: ubuntu
          command: ['expr', '3', '+', '2']
      restartPolicy: Never
```

```bash
kubectl get pods
# math-add-job-25j9p   0/1   Completed   0   2m
# math-add-job-87g4m   0/1   Completed   0   2m
# math-add-job-ds295   0/1   Completed   0   2m
```

> 기본적으로 Pod는 순차적으로 생성된다. 앞 Pod가 완료된 뒤에야 다음 Pod가 만들어진다.

---

## 6. 실패처리 - Job의 재시도
무작위로 성공/실패하는 이미지(`kubekloud/random-error`)로 Job을 만들면, 
Pod가 실패할 경우 성공 개수(completions)를 채울 때까지 새 Pod를 계속 생성한다.

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: random-error-job
spec:
  completions: 3
  template:
    spec:
      containers:
        - name: random-error
          image: kodekloud/random-error
      restartPolicy: Never
```

```bash
kubectl get pods
# random-error-job-ktmtt   0/1   Completed   0
# random-error-job-sdsrf   0/1   Error       0    ← 실패
# random-error-job-wwqbn   0/1   Completed   0
```
3개가 성공적으로 `Completed`될 때까지 Kubernetes는 새 Pod를 만든다.

---
## 7. 병렬 실행 - Parallelism
기본은 순차 생성이지만, `parallelism`필드로 동시에 여러 Pod를 실행할 수 있다.

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: random-error-job
spec:
  completions: 3
  parallelism: 3
  template:
    spec:
      containers:
        - name: random-error
          image: kodekloud/random-error
      restartPolicy: Never
```
동작: 먼저 3개를 한꺼번에 생성 -> 그 중 2개가 성공하면, 남은 1개가 완료될 때까지 지능적으로 필요한 만큼 Pod를 추가 생성한다.

---

## 8. CronJob
CronJob은 Job을 반복 스케줄로 실행한다. 리눅스의 crontab과 유사하다.
- `kubectl create`로 Job을 만들면 즉시 실행되지만, CronJob으로 감싸면 주기적으로 실행된다.
- **apiVersion**: `batch/v1beta1`(강의 기준), `batch/v1` 최신 K8s
- **kind: `CronJob`

**Job -> CronJob 변환**

기존 Job

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: reporting-job
spec:
  completions: 3
  parallelism: 3
  template:
    spec:
      containers:
        - name: reporting-tool
          image: reporting-tool
      restartPolicy: Never
```
CronJob으로 변환하면 spec이 3중 구조가 된다. 
`CronJob.spec` -> `jobTemplate.spec` -> `template.spec`(Pod) 중첩이 깊어지므로 특히 들여쓰기에 주의하자.

```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: reporting-cron-job
spec:
  schedule: "*/1 * * * *"
  jobTemplate:
    spec:
      completions: 3
      parallelism: 3
      template:
        spec:
          containers:
            - name: reporting-tool
              image: reporting-tool
          restartPolicy: Never
```
> `schedule`필드는 표준 Cron 형식 문자열을 사용한다. 
> `"*/1 * * * *"`는 매 1분마다 실행을 의미한다.

**생성 & 확인**
```bash
kubectl create -f cron-job-definition.yml
kubectl get cronjob
# NAME                 SCHEDULE      SUSPEND   ACTIVE
# reporting-cron-job   */1 * * * *   False     0
```

---
### Cron 형식

```
┌───────────── 분 (0-59)
│ ┌───────────── 시 (0-23)
│ │ ┌───────────── 일 (1-31)
│ │ │ ┌───────────── 월 (1-12)
│ │ │ │ ┌───────────── 요일 (0-6, 일=0)
│ │ │ │ │
* * * * *
```

예: `*/1 * * * *` (매 1분), `0 * * * *` (매시 정각), `0 0 * * *` (매일 자정).

---
### CKAD 핵심 정리
- Job vs ReplicaSet: ReplicaSet은 항상 N개 실행 유지, Job은 작업이 성공 완료될 때까지 실행
- Pod의 `restartPolicy`기본값은 `Always` -> 일회성 작업에는 부적합. Job/Pod에서는 `Never` or `OnFailure`로 설정
- Job: `apiVersion: batch/v1`, `kind: Job`. Pod 정의는 `spec.template.spec`에 들어감
- `completions`: 성공해야 하는 Pod 총 개수
- `parallelism`: 동시에 실행할 Pod 개수
- Job은 실패한 Pod를 재시도하여 `completions`를 채움.(`backoffLimit`로 재시도 한도 설정 가능)
- CronJob: Job을 스케줄 반복 실행. spec 3중 구조(`CronJob.spec` -> `jobTemplate` -> `template`)
- `schedule`: 표준 Cron 형식(분 시 일 월 요일)
- apiVersion 주의: 강의는 CronJob을 `batch/v1beta1`이라 썼지만 시험환경(1.3x)에서는 `batch/v1`
- 명령어: `kubectl get jobs`, `kubectl get cronjob`, `kubectl logs <pod>`, `kubectl delete job <name>`
- 시험 팁: 명령형으로 빠르게 생성
  - `kubectl create job my-job --image=busybox -- <command>`
  - `kubectl create cronjob my-cj --image=busybox --schedule="*/1 * * * *" -- <command>`
