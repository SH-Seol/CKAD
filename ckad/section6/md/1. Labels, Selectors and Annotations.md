# Labels, Selectors and Annotations
> Kubernetes가 클러스터 안의 오브젝트들을 그룹화하고 관리하기 위해
> 레이블(Labels), 셀렉터(Selector), 어노테이션(Annotations)을 어떻게 사용하는지 정리한다.
> 대규모, 동적 환경을 다룰 때 반드시 이해해야 하는 개념

---
## 1. Label, Selector
Label과 Selector는 항목을 그룹화하고 필터링하는 표준적인 방법이다.

온라인 스토어의 상품 필터, Youtube의 영상 태그와 같다. 
각 항목에 속성(label)을 붙여두고, 셀렉터(selector)로 그 속성을 기준으로 필터링한다.

예를 들어 여러 동물 집합이 있을 때

- 종류(class)로 필터링 → "포유류"만 보기
- 색깔(color)로 필터링 → "녹색 동물"만 보기
- 여러 조건 조합 → "녹색이면서 새인 동물"만 보기

즉, 어떤 분류 기준이든 필요에 따라 항목을 묶고 골라낼 수 있게 해주는 것이 Label, Selector이다.

#### Kubernetes에서 사용

Kubernetes에서는 Pod, Service, ReplicaSet, Deployment 등 다양한 오브젝트를 만든다. 
클러스터가 커지면 이런 오브젝트가 수백, 수천 개가 될 수 있다.

이 때 유형별, 애플리케이션별, 기능별로 오브젝트를 그룹화하고 골라내야 하는데, 각 오브젝트에 레이블(app, function) 등을 붙여두고,
선택할 때 조건(ex. `app=App1`)을 지정해 원하는 오브젝트만 필터링한다.

---
## 2. Kubernetes에서 레이블 지정하기

레이블은 Pod 정의 파일의 `metadata`섹션 아래에 key-value 쌍으로 지정한다. 원하는 만큼 추가할 수 있다.

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: simple-webapp
  labels:
    app: App1
    function: Front-end
spec:
  containers:
    - name: simple-webapp
      image: simple-webapp
      ports:
        - containerPort: 8080
```

Pod가 생성된 뒤, Label을 기준으로 선택하려면 `--selector` 옵션을 사용한다.

```bash
kubectl get pods --selector app=App1
```

## 3. ReplicaSet에서 Label, Selector 사용하기
Kubernetes의 오브젝트들은 내부적으로 Label, Selector를 사용해 서로를 연결한다.
ReplicaSet이 여러 Pod를 관리할 때, ReplicaSet의 Selector가 Pod의 Label과 일치하는 Pod들을 찾아 관리한다.

```yaml
apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: simple-webapp
  labels:
    app: App1
    function: Front-end
  annotations:
    buildVersion: "1.34"
spec:
  replicas: 3
  selector:
    matchLabels:
      app: App1
  template:
    metadata:
      labels:
        app: App1
        function: Front-end
    spec:
      containers:
        - name: simple-webapp
          image: simple-webapp
```

위 파일에 label은 두 곳에서 등장한다. 이들을 구분하자.

| 위치                          | 의미                   |
|-----------------------------|----------------------|
| 상단 `metadata.labels`        | ReplicaSet 자체의 label |
| `template.metadata.labels`  | 생성되는 Pod에 붙는 레이블     |
| `spec.selector.matchLabels` | ReplicaSet이 어떤 Pod를 관리할지 찾는 조건 |

- 지금 목표는 ReplicaSet이 Pod를 찾아 관리하게 하는 것, `selector`가 Pod 템플릿의 레이블과 일치하도록 맞추는 것이 핵심
- 상단 ReplicaSet 자체 label은 다른 오브젝트가 이 replicaSet을 찾을 때 활용된다.
- label이 올바르게 일치하면 하나의 레이블(ex. `app: App1`)만으로도 충분
- label은 같지만 다른 pod가 섞여 있을 수 있으므로, 여러 label 함께 지정하면 의도치 않은 매칭 피하고 정확한 pod 고를 수 있음.

레이블이 일치하면 ReplicaSet이 성공적으로 생성된다.

#### Service도 마찬가지
서비스 또한 정의 파일의 selector가 pod에 설정된 label과 일치하면 해당 pod 들을 서비스 대상으로 연결한다.

## 4. Annotations
- Label, Selector → 오브젝트를 그룹화하고 선택하는 용도
- Annotation → 식별에 쓰이지 않는 부가 정보를 기록하는 용도

어떤 내용을 담을까?
- 도구 정보: 이름, 버전, 빌드 정보 등(ex. `buildversion: "1.34`)
- 연락처 정보: 전화번호, 이메일 등 통합 목적의 정보

어노테이션은 오브젝트의 그룹화나 선택에는 영향을 주지 않으며, 외부 시스템이나 프로세스가 오브젝트의 메타데이터를 참조해야 할 때 유용


---

핵심정리

- 레이블(Labels) : metadata.labels에 key-value로 지정. 그룹화의 기준.
- 셀렉터(Selectors) : 레이블을 기준으로 오브젝트를 필터링/연결.
- `kubectl get pods --selector app=App1 (= -l app=App1)` : 레이블로 Pod 조회. 
  - 여러 조건: `-l app=App1,function=Front-end`
- ReplicaSet/Deployment의 핵심은 `selector` — `spec.selector.matchLabels`가 `spec.template.metadata.labels`와 반드시 일치해야 함. (불일치 시 생성 에러)
- 레이블이 두 군데 있음에 주의:
  - `metadata.labels` = 오브젝트(ReplicaSet) 자체의 레이블 
  - `template.metadata.labels` = 생성될 Pod의 레이블 ← selector가 이걸 보고 매칭
- Service ↔ Pod 연결도 셀렉터 ↔ 레이블 매칭으로 동작.
- 어노테이션(Annotations) : 식별/선택과 무관한 부가 정보(빌드 버전, 연락처 등) 저장용. 셀렉터로 필터링 ❌.
- 시험 팁:
  - `kubectl get pods --show-labels` : 모든 Pod의 레이블 표시. 
  - `kubectl label pod <pod> tier=frontend` : 레이블 추가/수정. 
  - `kubectl get pods -l 'env in (dev,prod)'` : 집합 기반(set-based) 셀렉터.
