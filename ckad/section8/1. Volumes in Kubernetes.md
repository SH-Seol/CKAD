# 1. 쿠버네티스 볼륨 (Volumes in Kubernetes)
> Pod는 일시적(ephemeral)이라 삭제되면 내부 데이터도 사라진다. 
> 볼륨(Volume)을 붙이면 Pod가 만든 데이터를 Pod 수명과 무관하게 보존할 수 있다.

---

## 0. 배경 - Docker Storage
컨테이너(및 Pod)의 쓰기 레이어는 휘발성이라, 컨테이너가 사라지면 그 안의 데이터도 함께 사라진다.
그래서 Docker에서는 컨테이너에 볼륨을 붙여 데이터를 컨테이너 밖(호스트나 외부 스토리지)에 저장했고, 
Kubernetes도 똑같은 발상으로 Pod에 볼륨을 붙여 데이터를 영속화한다.
이 휘발성 -> 볼륨으로 영속화 원칙 하나가 아래 k8s 볼륨/PV/PVC 전체를 관통한다.

---

## 1. 쿠버네티스에서의 볼륨
- Docker 컨테이너처럼, Kubernetes의 Pod도 일시적(transient)이다. 데이터를 처리하려고 Pod를 만들고 삭제하면, 별도로 저장하지 않은 데이터는 사라진다.
- Pod에 볼륨을 붙이면, Pod가 볼륨에 쓴 데이터는 Pod가 종료된 후에도 남는다.

---
## 2. 간단 예제
1~100 사이 난수를 생성해 `/opt/number.out`에 기록하는 Pod이다. 볼륨이 없으면 Pod삭제 시 난수도 사라진다.

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: random-number-generator
spec:
  containers:
    - name: alpine
      image: alpine
      command:
        - "/bin/sh"
        - "-c"
      args: ["shuf -i 0-100 -n 1 >> /opt/number.out;"]
```

**볼륨을 붙여 데이터 보존**
호스트 `/data`디렉터리를 볼륨의 저장소로 쓰고, 이를 컨테이너 내부 `/opt`에 마운트한다.
그러면 `/opt/number.out`에 쓴 파일이 실제로는 호스트의 `/data`에 저장되어 Pod가 사라져도 데이터가 남는다.

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: random-number-generator
spec:
  containers:
    - name: alpine
      image: alpine
      command:
        - "/bin/sh"
        - "-c"
      args: ["shuf -i 0-100 -n 1 >> /opt/number.out;"]
      volumeMounts:
        - mountPath: /opt
          name: data-volume
  volumes:
    - name: data-volume
      hostPath:
        path: /data
        type: Directory
```

핵심 구조
- `volumes`(Pod 레벨): 볼륨을 정의하고 이름을 붙임(`data-volume`). 저장소로 `hostPath`(호스트의 `/data`)사용
- `volumeMounts`(컨테이너 레벨): 그 볼륨을 컨테이너 내부 경로(`mountPath: /opt`)에 마운트, `name`으로 위 볼륨과 연결

> 즉 `volumes`(어디에 저장할지) + `volumeMounts`(컨테이너 어디에 붙일지)를 `name`으로 짝지어 주는 구조이다.
> `hostPath`는 단일 노드에서만 적합하다. 멀티 노드 클러스터에서는 각 노드의 `/data`가 서로 다른 디스크라 데이터가 일관되지 않으므로 권장되지 않는다.

---
## 3. 볼륨 스토리지 옵션

`hostPath`필드를 `awsElasticBlockStore`로 바꾸고 볼륨ID와 파일 시스템 타입을 지정한다.
```yaml
volumes:
  - name: data-volume
    awsElasticBlockStore:
      volumeID: <volume-id>
      fsType: ext4
```

-> 이제 볼륨 데이터가 호스트가 아니라 AWS EBS에 저장되어, 멀티 노드 환경에서도 안정적으로 관리된다.

---
### CKAD 핵심 정리
- 원칙: Pod는 휘발성 -> 데이터 영속화를 하려면 볼륨 필요
- 두 필드의 짝:
  - `spec.volumes` - 볼륨 정의(이름 + 저장소 종류)
  - `spec.containers[].volumeMounts` - 컨테이너 내부 `mountPath`에 마운트(`name`으로 볼륨과 연결)
- `hostPath`: 노드의 디렉토리를 볼륨으로 사용. 단일 노드 전용. 멀티 노드에는 부적합
- 스토리지 종류 교체는 `volumes`아래 필드만 바꾸면 됨(`hostPath` -> `awsElasticBlockStore`, `nfs` 등)
- 지원 스토리지: NFS, GlusterFS, AWS EBS, GCP PD 등
- hostPath로 빠르게 볼륨 붙이는 YAML 구조(`volumes` + `volumeMounts`)는 익혀두자
