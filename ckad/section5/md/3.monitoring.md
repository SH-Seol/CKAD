# Monitoring

## 1. 왜 Kubernetes를 모니터링하는가?
클러스터의 상태와 성능을 유지하려면 다음과 같은 메트릭을 추적해야 한다.

- 노드 수준 메트릭(Node-Level): 전체 노드 수, 정상 노드 수, 노드의 전반적인 성능
- 성능 메트릭(Performance): CPU 메모리, 네트워크, 디스크 사용률
- 파드 수준 메트릭(Pod-Level): 파드의 개수, 개별 파드의 CPU, 메모리 사용량

이런 메트릭을 효율적으로 수집, 집계, 분석하려면 모니터링 솔루션이 필요하다. Kubernetes에는 built-in 모니터링 솔루션이 없어 외부 도구를 가져와야한다.
- 오픈소스: Metric Server, Prometheus, Elasic Stack
- 상용: Datadog, Dynatrace

> Metric Server는 가볍고 인메모리(in-memory)방식의 모니터링 솔루션으로, 실시간 메트릭 수집에 적합.
> 단 데이터를 디스크에 저장하지 않아 과거 이력 조회 불가.

---

## 2. 매트릭은 어떻게 수집되는가?

- 클러스터의 각 노드에는 kubelet 에이전트가 실행된다. 
kubelet은 Kubernetes API 마스터 서버로부터 명령을 수신하고, 노드에서 파드를 실행하는 역할을 한다.
- kubelet에는 cAdvisor(Container Advisor)라는 하위 구성 요소가 포함되어 있다.
- cAdvisor가 파드에서 성능 메트릭을 수집하고, 이를 kubelet API를 통해 노출하여 Metrics Server가 사용할 수 있도록 한다.

`파드 -> cAdvisor -> (kubelet API) -> Metrics Server`

## 3. 클러스터 메트릭 확인

```bash
#노드 메트릭
kubectl top node
#파드 메트릭
kubectl top pod
```

시험 팁: 자주 쓰는 추가 옵션

- kubectl top pod --containers : 파드 내 컨테이너별 사용량까지 표시.
- kubectl top pod -l <label> : 라벨로 필터링.
- kubectl top pod --sort-by=cpu (또는 memory) : 사용량 순 정렬.
