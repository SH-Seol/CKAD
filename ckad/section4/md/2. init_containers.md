# InitContainers

### 1. 멀티 컨테이너 Pod의 기본 동작
멀티 컨테이너 Pod에서 각 컨테이너는 Pod의 라이프 사이클과 함께 살아 있어야 한다.
- 웹 애플리케이션 컨테이너 + 로그 에이전트 컨테이너
- 두 컨테이너 모두 항상 실행 중
- 어느 하나라도 실패하면 Pod 재시작

---

### 2. initContainers가 필요한 상황
일반 컨테이너와 달리 한 번만 실행되고 완료되어야 하는 작업이 필요할 때 사용

| 사용사례            | 예시                     |
|-----------------|------------------------|
| 코드/바이너리 사전 다운로드 | git clone으로 앱 소스 받아오기  |
| 외부 서비스 준비 대기    | DB와 같은 외부 서비스 뜰 때까지 대기 |

핵심: 메인 컨테이너가 시작되기 전에 완료되어야 하는 작업

---

### 3. initContainers 기본 구조
`spec.initContainers`섹션에 정의한다. 보면 `containers`와 문법은 다르지 않다.

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: myapp-pod
  labels:
    app: myapp
spec:
  containers:
    - name: myapp-container
      image: busybox:1.28
      command: ['sh', '-c', 'echo The app is running! && sleep 3600']
  initContainers:
    - name: init-myservice
      image: busybox
      command: ['sh', '-c', 'git clone <some-repository> ;']
```

---

### 4. 실제 예시

`nslookup`으로 의존 서비스가 DNS에 등록될 때까지 루프를 돌며 대기한다.

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: myapp-pod
  labels:
    app: myapp
spec:
  containers:
    - name: myapp-container
      image: busybox:1.28
      command: ['sh', '-c', 'echo The app is running! && sleep 3600']
  initContainers:
    - name: init-myservice #1
      image: busybox:1.28
      command: ['sh', '-c', 'until nslookup myservice; do echo waiting for myservice; sleep 2; done;']
    - name: init-mydb #2
      image: busybox:1.28
      command: ['sh', '-c', 'until nslookup mydb; do echo waiting for mydb; sleep 2; done;']
```

---

### 5. initContainers 동작 규칙

```text
[init-container-1] → 완료
        ↓
[init-container-2] → 완료
        ↓
    [main container 시작]
```
1. 순차 실행: 여러 initContainer가 있을 경우 정의된 순서대로 하나씩 실
2. 완료 후 다음 단계: 각 initContainer가 성공적으로 완료되어야 다음으로 진행 
3. 실패 시 Pod 재시작: initContainer가 실패하면 Kubernetes는 성공할 때까지 Pod를 반복 재시작

---

### 6. 일반 컨테이너 vs initContainers
| 항목 |일반 컨테이너|initContainers|
|----|--|----|
| 실행 시점| Pod 실행 내내| 메인 컨테이너 시작 전에만| 
|실행 방식| 병렬 실행|순차 실행|
|완료 여부|계속 실행 중이어야 함|반드시 완료(exit 0) 되어야 함|
|실패 시|Pod 재시작|Pod 재시작 (성공까지 반복)|

---

### 요약
> initContainers는 메인 앱 컨테이너가 시작되기 전에 완료되어야 하는 초기화 작업을 위한 컨테이너다.

- spec.initContainers 섹션에 정의 (일반 컨테이너와 동일한 문법)
- 여러 개 정의 가능 → 정의 순서대로 순차 실행
- 모든 initContainer가 성공(exit 0) 해야 메인 컨테이너 시작
- 실패 시 Pod 전체를 재시작 (성공할 때까지 반복)
- 주요 사용 사례:

- 코드/설정 파일 사전 다운로드
- DB, 외부 서비스 기동 대기 (until nslookup ...)
